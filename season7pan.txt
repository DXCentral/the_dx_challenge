Here is the complete, memorialized blueprint for The DX Challenge: Season 7, including our design philosophy, technical architecture, and strict development protocols.
🎨 1. THEME & UI/UX (THE AMBER TERMINAL)
The Aesthetic: A clean, high-signal, zero-noise technical terminal. All previous "Cold War/Espionage" gimmicks have been permanently retired.
Color Palette & Typography: Deep warm black (#0d0a00) backgrounds, classic terminal amber (#ffb000) text/accents, and exclusive use of the Fira Code monospace font.
Terminology: Standardized and accessible. "Log Entries" instead of "Intercept Reports," "Leaderboard" instead of "Clandestine Matrix."
Navigation Architecture (The "No Sidebar" Rule): The native Streamlit collapsible sidebar is completely eliminated to prevent user lockouts. Navigation is strictly handled via a permanent, un-hideable top-navigation bar using st.pills (e.g., [ HOME ], [ SUBMIT INTERCEPT ]).
Traffic Routing: dxchallenges.com remains the permanent, static URL for the community, which you will dynamically point to the active Season 7 Streamlit app/repository.
🏗️ 2. SYSTEM ARCHITECTURE & PERFORMANCE
Tech Stack: Python, Streamlit, Pandas, Plotly (charts), PyDeck (maps), and Google Sheets (backend).
The API Bypass: To eliminate load-time bottlenecks, the app will never use slow, row-by-row Google Sheets APIs to read data. It will fetch the published Master Sheet directly as a raw CSV (pd.read_csv).
In-Memory Data Forge: Your 5 seasons of legacy MW Frequency Challenge data (38,200+ rows) will live in the GitHub repository as a static CSV. Upon launch, the app concatenates the live Season 7 Sheet and the legacy CSV directly in RAM. Aggressive Pandas pre-filtering ensures instantaneous leaderboard and map rendering.
Lightweight Authentication: Frictionless secure login using streamlit_javascript to read/write the DXer's profile (Name, Location, Lat/Lon) to their browser's localStorage.
⚙️ 3. THE "FORM LOCKER" (challenge_rules.py)
This central configuration file acts as the automated brain of the application.
The State Machine: Challenges are defined in a Python array with strict start_utc and end_utc timestamps. The app continuously checks the live UTC clock against this array to determine what is active.
Automated UI Lockdown: At exactly 0200 UTC on changeover days, the platform automatically reconfigures the submission forms and leaderboards based on the active ruleset (e.g., locking the MW form strictly to 910 kHz for a sprint).
Concurrent Operations: Allows massive, season-long marathons (e.g., Season 7 FM/NWR) to run seamlessly in the background while highly restrictive, short-term sprints rotate on top of them. You never have to manually update the home page or rebuild forms.
💾 4. THE DATA SCHEMA & DUAL-TAGGING
All submissions flow into a single Master Google Sheet, eliminating the need for weekly database spin-ups.
The Dual-Tag Payload: When a user transmits a log, the app reads challenge_rules.py and silently appends two discrete metadata tags to the row: Season (e.g., "Season 7") and Sprint/Week (e.g., "Week 1 | The Launch Sprint").
Single-Log/Multi-Board: This allows a single submitted catch to automatically populate both the specific weekly sprint leaderboard and the cumulative season-long marathon leaderboards without duplicate data entry.
Column Upgrades: The Master Sheet has been successfully upgraded. "AM or FM?" has been changed to "Band?", "NWR Frequency" has been added to maintain data hygiene, and the Season and Sprint/Week columns are anchored at the end.
